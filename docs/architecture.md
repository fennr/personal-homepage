# Как устроено

Один бинарь на Axum: маршруты, шаблоны Askama и статика. Контент, шаблоны,
стили и шрифты вкомпилированы в образ, поэтому «что в репозитории» и «что на
сервере» не могут разойтись. Сервер без состояния: ни базы, ни сессий, ни
cookies.

## Режимы

| Адрес | Что это |
|---|---|
| `/` | Обычная версия: светлый документ — профиль, полоса карьеры, стек, опыт, проекты, контакты |
| `/terminal` | Терминальная версия: тёмная консоль с приглашением `visitor@fennr:~$` |

Режим задаётся только адресом и нигде не запоминается: терминал открывают по
запросу, это не настройка. Оба режима печатают одну модель `Site`, поэтому
новый факт появляется в контенте один раз и сразу виден в обоих.

Терминал понимает `help`, `about`, `stack`, `work`, `projects`, `contact`,
`resume`, `ls`, `cat <раздел>` и `clear`. Ответ — чистая функция от ввода и
контента (`terminal::answer`); неизвестная команда печатает ошибку и
подсказку, а не тишину.

## Маршруты

| Маршрут | Что отдаёт |
|---|---|
| `GET /` | обычная версия |
| `GET /terminal` | терминальная версия с приветствием и справкой |
| `POST /terminal/exec` | фрагмент вывода; без заголовка `HX-Request` — целую страницу |
| `GET /terminal/exec?cmd=` | то же для подсказок-ссылок |
| `GET /robots.txt`, `GET /sitemap.xml` | индексация |
| `GET /healthz` | `ok`, ответ на проверку живости |
| `GET /static/*` | CSS, шрифты, картинки, htmx; `ETag`, `Content-Type`, кэш |

Подсказки — ссылки с `href` и `hx-get`: без JS они работают как обычные
переходы, с htmx дописывают фрагмент в вывод. Единственный клиентский скрипт —
htmx из образа; сброс поля, фокус и прокрутку после ответа делает
`hx-on::after-request` на форме.

## Модули

```
src/main.rs        запуск, PERSONAL_HOMEPAGE_BIND, подкоманды health и resume
src/content/       контент: разбор TOML, правила, единая модель
  model.rs         структуры файлов, deny_unknown_fields
  date.rs          YearMonth и End ("now" у текущего места работы)
  span.rs          стаж, отрезки полосы, ось лет
  error.rs         ContentError: «файл: поле: что не так»
src/terminal/      команды и текстовые ответы, без HTTP
src/resume/        JSON для PDF-резюме: то же представление, что у страницы
src/web/           маршруты, шаблоны, статика
  view.rs          то, что печатается: месяцы словами, склонение стажа
  static_files.rs  include_dir!, ETag, Content-Type, кэш
templates/         base.html, index.html, terminal.html, partials/answer.html
resume/            resume.typ, data.json и шрифты для PDF
scripts/fonts      нарезка шрифтов по алфавитам
static/            app.css, terminal.css, нарезанные шрифты, htmx.min.js, resume.pdf
tests/             content.rs — правила, terminal.rs и web.rs — HTTP
```

## PDF-резюме

PDF не собирается сервером: `just resume` печатает данные подкомандой
`resume`, Typst верстает по ним файл в `static/resume.pdf`, и тот уезжает в
образ как обычная статика. На сайте остаётся ссылка, а страница печатает её
только при наличии файла.

## Статика

Файлы лежат в бинаре (`include_dir!`), `ETag` считается один раз на старте из
байтов файла, поэтому повторный запрос получает `304`. У стилей имя без хеша —
они перепроверяются (`must-revalidate`), а шрифты и картинки живут в кэше
неделю. Ссылка на резюме печатается только тогда, когда файл есть в статике:
битая кнопка хуже отсутствующей.

## Тесты

Гейт — `just check`. Правила контента проверяются на испорченных копиях
`content/` (сообщение обязано называть файл и поле), HTTP-слой — запросами к
собранному приложению. Эталонных снимков HTML нет: они ломаются от правки
текста.
