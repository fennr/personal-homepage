# Решения: личная страница fennr.ru

Записано до начала реализации, чтобы через полгода было видно не только «что»,
но и «почему». Решения принимались в диалоге; каждый пункт — либо выбор из
нескольких вариантов, либо отказ от варианта с причиной.

## Продукт

| Решение | Почему |
|---|---|
| Основной читатель — нанимающий менеджер или техлид; второй — разработчик с GitHub | Страница читается между делами; поэтому документ, а не витрина |
| Главное действие — написать в Telegram, затем «Резюме, PDF» | Нанимателю нужен файл для HR-системы, а ответ ждут в мессенджере: почта в шапке проигрывала по скорости и осталась в подвале вместе с остальными контактами |
| Язык только русский, латиницей — технические имена | Двуязычие удваивает объём текста и требует `hreflang`; отдельная работа, если появится причина |
| Ссылки на self-hosted сервисы (travel, memo, task) не ставим | Они закрыты Tinyauth: читатель получит форму входа вместо проекта |
| Блоки: профиль, о себе, стек, опыт, проекты, контакты | «Основной/дополнительный стек» и «хобби» дублировали друг друга; стек — одна таблица, хобби-проекты переехали в проекты |
| Проектов шесть, Samuro исключён | Samuro — бот для игры; для нанимателя это шум рядом с библиотекой и CLI |
| Детализация опыта падает с давностью | Четыре работодателя с 2018 года: у текущего — пункты, у давних — одна строка |
| Резюме PDF собирается из тех же данных шаблоном Typst | Иначе через полгода PDF разойдётся со страницей; прежний файл от 2024-11 уже устарел |
| PDF собирается локально (`just resume`) и лежит в git | Образ собирается из вкомпилированной статики, а данные резюме печатает сам бинарь: собрать PDF внутри сборки образа нельзя без курицы и яйца. Свежесть держит тест: он пересобирает данные и сравнивает с закоммиченными |
| Шрифты для Typst — TTF в `resume/fonts` | В `static/fonts` лежат woff2-подмножества для браузера, Typst их не читает; узкое начертание из Google Fonts приезжает со сломанным именем семейства, поэтому в резюме одно семейство IBM Plex Sans |
| В браузере одно семейство IBM Plex Sans с осями веса и ширины | Отдельное семейство Condensed приезжало без кириллицы, и заголовки на русском молча рисовались системным шрифтом; ось ширины в вариативном файле даёт то же узкое начертание для всех алфавитов |
| Шрифт нарезан по алфавитам, а не по символам контента | Нарезка по фактическим символам даёт файл вдвое меньше, но любая правка текста требует пересборки: забыли — и буква уехала в системный шрифт. Набор «латиница, Latin-1, кириллица, типографика» покрывает любые правки, а тест ловит символ вне набора |

## Режимы

| Решение | Почему |
|---|---|
| `/` — обычная версия, `/terminal` — терминальная, состояние только в URL | Запоминание выбора в localStorage превращает режим в настройку, а включать его нужно только по запросу |
| Терминал — оболочка с фиксированным списком команд на сервере | htmx здесь без компромиссов: `hx-post` и фрагмент ответа; никакого `eval` и клиентского парсера |
| Команды: `help`, `about`, `stack`, `work`, `projects`, `contact`, `resume`, `ls`, `cat`, `clear` | `ls`/`cat` дают терминальную привычку без состояния; `cd` не делаем — он требует текущего каталога |
| Подсказки следующими командами вместо Tab и истории | Tab и история требуют клиентского JS; ссылки работают и без него |
| Свой сервис вместо LiveTerm | LiveTerm показывает страницу как файловую систему: читателю-человеку это неудобно, а сборка (`npm install` + dev-сервер) тяжела для VPS. Терминал остаётся, но как второй режим, а не единственный |
| LiveTerm остаётся на `old-home.fennr.ru` две недели, потом удаляется | Сравнить глазами — единственная причина держать старый сервис; строка в палитре бренда удаляется вместе с ним |

## Техника

| Решение | Почему |
|---|---|
| Rust, Axum, Askama | Партиалы для htmx проверяются на этапе компиляции; maud дороже в правке текста, MiniJinja даёт рантайм-ошибки |
| Контент — `content/*.toml` через `include_str!`, разбор на старте | Один источник для двух режимов; образ и контент не расходятся; правка текста не требует шаблона |
| Без базы, сессий и cookies | Историю команд держит DOM; серверу нечего помнить |
| Статика через `include_dir!`, `ETag`, `CompressionLayer` | Один артефакт, нет расхождения с рабочим каталогом; перед сервисом только traefik, он не сжимает |
| Образ distroless-static (musl) и подкоманда `health` | Нет shell и curl: 10 МБ вместо 90; `HEALTHCHECK` в exec-форме работает без оболочки |
| Один крейт с модулями `content`, `web`, `terminal`, `templates` | Workspace оправдан при переиспользовании; здесь всё живёт ради одного бинаря |
| CI: job `check` (fmt, clippy, test) и job `build` (GHCR) | У nomad-notes гейт качества локальный только из-за фронтенд-сборки; здесь `check` занимает секунды |
| Репозиторий `fennr/personal-homepage`, образ `ghcr.io/fennr/personal-homepage`, сервис `services/personal-homepage`, порт 8080 | Имена не пересекаются с каталогом иконок бренда `home` |
| Тег `vX.Y.Z` двигает `just release`, на теге сверяется версия `Cargo.toml` | Схема nomad-notes: одна версия, один источник |

## Дизайн

Выбран вариант **A** — «проектная документация» из двух черновиков
(`docs/prototype/a-dossier.html`). Он даёт контраст режимов: светлый документ
против тёмной консоли. Вариант B («системная схема», тёмный) отклонён, потому
что забирал эффект у терминального режима.

Токены:

| Роль | Значение |
|---|---|
| Бумага | `#F1F2EE` |
| Бумага для заливок | `#DFE1DA` |
| Чернила | `#16191B` |
| Второй план | `#4E585C` |
| Линии | `#C6C9C2` |
| Акцент | `#1C4E80` (чертёжная синь) |
| Заголовки | IBM Plex Sans 600, ширина 75 % |
| Текст | IBM Plex Sans 400/500 |
| Цифры | табличные (`font-variant-numeric: tabular-nums`), не моноширинный |
| Герой | полоса карьеры 2018→2026, текущий отрезок в акценте; слева давнее, справа текущее |

Уточнения, принятые при реализации: месяцы считаются включительно (ноябрь уже
стаж, поэтому с сентября 2018 стаж — 99 месяцев, «8 лет 3 месяца»), каждый
отрезок полосы подписан своим `brand` — латиницей и в одном написании у всех
мест, а на узком экране подписи меньше пятой части полосы скрываются —
расшифровка есть в списке опыта. Подпись под полосой из черновика («от ABAP до
архитектуры») не перенесена: это текст, а текст живёт в контенте.

Терминальная версия: фон `#14181B`, текст `#D7DDE0`, акцент `#6E9BC9`
(исходная синь не проходит по контрасту на тёмном), JetBrains Mono,
приглашение `visitor@fennr:~$`. Палитру Nord не берём — это палитра LiveTerm.

Уточнения к образу и CI, принятые при реализации:

- Сборка переехала с `rust:bookworm` + `musl-tools` на `rust:alpine`: на
  bookworm линкер отказывался собирать musl-цель (`cc: unrecognized
  command-line option '-m64'`), а в alpine musl родной и целевой флаг не нужен.
- Итоговый образ — 6.7 МБ, запускается с `read_only: true` (проверено), а
  `HEALTHCHECK` переходит в `healthy` за 6 секунд.
- `compose-check` из набора nomad-notes здесь не нужен: compose живёт в
  homelab, а не в этом репозитории.
- Тулчейн в CI обновляется через `rustup`, сторонние actions для Rust не
  используются — только `actions/*` и `docker/*`.
- `just release` умеет выпускать первую версию без коммита: если версия в
  `Cargo.toml` уже совпадает, ставится только тег.

Уточнения к терминальному режиму, принятые при реализации:

- `clear` очищает вывод через out-of-band своп (`hx-swap-oob="innerHTML"`), а не
  отдельным маршрутом: команда остаётся командой, а форме не нужны исключения.
- Без JS форма отправляется обычным POST и возвращает целую страницу с ответом;
  история в этом режиме не накапливается — её держит только DOM при htmx.
- В терминале даты печатаются как `2024-05`: моноширинному тексту это роднее, а
  словами месяцы пишутся в обычной версии.
- Одна строка встроенного JS на форме (`hx-on::after-request`): очистить поле и
  вернуть фокус. Отказ от неё означал бы, что после Enter ввод остаётся
  заполненным.
- Прокрутка вывода висит на самой ленте (`hx-on::after-swap` у `#out`), а не на
  форме: строки дописывают и форма, и подсказки-ссылки, поэтому новый текст
  должен быть виден после любого ответа.
- Черновик дизайна удалён из `docs/prototype` после реализации: решения
  записаны здесь, а сам файл остаётся в истории git.
