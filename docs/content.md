# Контент

Текст страницы живёт только в `content/*.toml`: в шаблонах остаются лишь
подписи интерфейса. Файлы вкомпилированы через `include_str!`, разбираются и
проверяются на старте — сервис с непроверенными данными не запускается.

| Файл | Что описывает |
|---|---|
| `profile.toml` | имя, роль, одно предложение о себе, абзацы «О себе», резюме, контакты |
| `stack.toml` | группы технологий по назначению |
| `experience.toml` | места работы — от текущего к давнему |
| `projects.toml` | публичные проекты |

## Правила

Ошибка называет файл, поле и что не так:

```
experience.toml: roles[3].end: 2019-01 раньше начала 2020-01
```

- Обязательные поля непустые; незнакомое поле — ошибка, а не молча
  проигнорированный текст.
- Даты в формате `YYYY-MM`. У текущего места работы `end = "now"`, и оно идёт
  первым в файле.
- Места работы идут от нового к давнему, конец не раньше начала.
- У места работы два имени: `company` для текста и `brand` для полосы карьеры.
  `brand` пишется латиницей и одинаково у всех мест («BC Soft», а не «Бизнес
  Компьютер Софт»), иначе соседние подписи оказываются в разных алфавитах.
- `emphasis` в группе стека обязан входить в её `items`.
- Контакты идут в порядке вывода: первый печатается кнопкой в шапке, поэтому
  первым стоит тот, кому пишут чаще.
- Ссылки на проекты абсолютные; контакты — `https://`, `mailto:` или `/`.

Проверки две: `cargo test` гоняет правила на копиях контента и на самом
репозитории, а `just content-check` собирает и запускает бинарь — проверка идёт
на старте, до открытия порта, поэтому ошибка печатается вместо запуска сервера.

## Даты и стаж

Месяцы считаются включительно: месяц, в котором человек работал хотя бы часть
времени, считается целым. Поэтому с сентября 2018 по ноябрь 2026 — 99 месяцев,
то есть «8 лет 3 месяца». Полоса карьеры строится из тех же дат: длина отрезка —
число месяцев, подпись — `brand` компании.

## Картинка для соцсетей

`static/og.png` — растр, текст в нём не может прийти из `content/`, поэтому имя,
роль и стаж повторяются в макете `docs/og.html`. После правки шапки картинку
перегенерируют:

```sh
npx playwright screenshot --viewport-size=1200,630 docs/og.html static/og.png
```

## PDF-резюме

`static/resume.pdf` собирается из тех же данных, что и страница: бинарь
печатает JSON (`personal-homepage resume`), Typst верстает по нему PDF.

```sh
just resume    # данные + PDF (нужен typst: brew install typst)
```

- `resume/data.json` — данные на момент сборки, лежат в git;
- `resume/resume.typ` — вёрстка A4, палитра и шрифты те же, что на странице;
- `resume/fonts` — IBM Plex Sans трёх начертаний (OFL, текст лицензии рядом).

Даты, стаж и склонения приходят уже посчитанными из представления страницы,
поэтому в шаблоне нет ни одной текстовой строки, кроме подписей разделов.

Тест `tests/resume.rs` пересобирает данные на записанный в них месяц и
сравнивает с файлом: если контент поправили, а `just resume` не запускали, гейт
падает и просит пересобрать. Кнопка на странице появляется сама — она
печатается только тогда, когда файл есть в статике.
