# personal-homepage

Личная страница [fennr.ru](https://fennr.ru): обычная версия для читателя и
терминальная — по запросу, из одного и того же контента.

Заменяет собой LiveTerm: тот эмулирует терминал и показывает контент как
файловую систему, но для читателя-человека это неудобно, а его сборка
(`npm install` + dev-сервер) тяжела для сервера. Здесь терминал остаётся, но
как второй режим, а не как единственный.

## Что уже есть

- Модель контента `content/*.toml` с проверкой инвариантов; ошибка называет
  файл и поле.
- Обычная версия страницы на `/`: светлый документ с полосой карьеры, стеком,
  опытом, проектами и контактами.
- Терминальная версия на `/terminal`: тёмная консоль с командами `help`, `about`,
  `stack`, `work`, `projects`, `contact`, `resume`, `ls`, `cat <раздел>`,
  `clear` и подсказками-ссылками. Работает и без JS: форма отправляется обычным
  POST и возвращает целую страницу.
- Шаблоны Askama, стили, шрифты и htmx вкомпилированы в бинарь, статика
  отдаётся с `ETag` и сжатием.
- Тесты: правила контента на битых входах, страница и статика — запросами к
  приложению.

Дальше по плану: выкат в homelab, снятие LiveTerm. Порядок шагов и принятые решения — в
[`docs/decisions.md`](docs/decisions.md).

## Структура

```
content/          profile.toml, stack.toml, experience.toml, projects.toml
src/content/      разбор, проверка правил, единая модель для обоих режимов
  date.rs         YearMonth и End ("now" у текущего места работы)
  model.rs        структуры TOML: deny_unknown_fields, Option для необязательного
  span.rs         стаж и полоса карьеры: месяцы, отрезки, ось лет
  error.rs        ContentError/ContentErrors: «файл: поле: что не так»
src/terminal/     разбор команд и текстовые ответы: чистая функция, без HTTP
src/web/          маршруты, шаблоны, статика из образа
  view.rs         то, что печатается: месяцы словами, склонение стажа
  static_files.rs ETag, Content-Type и кэш для /static/*
templates/        base.html, index.html, terminal.html, partials/answer.html
static/           app.css, terminal.css, fonts.css, шрифты, htmx.min.js
tests/            контент и HTTP-слой
docs/             решения и прототип дизайна
```

## Контент

Текст правится только в `content/*.toml`: шаблоны не содержат текста, а оба
режима читают одну модель. Правила:

- обязательные поля непустые;
- даты в формате `YYYY-MM`; у текущего места работы `end = "now"`, и оно идёт
  первым в файле;
- места работы — от нового к давнему;
- `emphasis` в группе стека обязан входить в её `items`;
- у места работы два имени: `company` для текста и `brand` для полосы карьеры —
  латиницей и в одном написании у всех мест («BC Soft» вместо «Бизнес
  Компьютер Софт»), иначе соседние подписи оказываются в разных алфавитах;
- контакты идут в порядке вывода: первый печатается кнопкой в шапке, поэтому
  первым стоит тот, кому пишут чаще; `handle` — адрес внутри сервиса (`@fenn_r`);
- ссылки на проекты абсолютные, контакты — `https://`, `mailto:` или `/`;
- незнакомое поле — ошибка, а не молча проигнорированный текст.

## Разработка

```sh
just check            # форматирование, clippy -D warnings, тесты
just serve            # страница на 127.0.0.1:8080
just content-check    # проверить content/ так же, как это сделает сервис
just hooks            # хук commit-msg с commitlint (нужен node)
just image            # образ локально: personal-homepage:local
```

## Сборка и релиз

Образ собирается на `rust:1.99-alpine` (musl) и уезжает в
`gcr.io/distroless/static-debian12:nonroot`: shell и curl внутри нет, поэтому
`HEALTHCHECK` вызывает сам бинарь — `personal-homepage health` делает
`GET /healthz` и возвращает код выхода. Итоговый образ — 6.7 МБ, работает с
`read_only: true`.

```sh
just image              # собрать и проверить локально
just release 0.2.0      # версия в Cargo.toml, коммит, тег v0.2.0
git push origin HEAD && git push origin v0.2.0
```

Workflow `Container` на каждый push гоняет `check` (fmt, clippy, тесты) и
собирает образ; публикация в `ghcr.io/fennr/personal-homepage` происходит только
по тегу `vX.Y.Z`, и тег обязан совпадать с версией в `Cargo.toml`.

Compose-файла здесь нет: сервис описан в репозитории `homelab`
(`services/personal-homepage`), туда же пинится версия образа.

Сообщения коммитов — Conventional Commits, трейлер `Co-authored-by` запрещён.
Версия проекта живёт в `Cargo.toml`; node в CI не участвует.
